# Autoglia Evaluation Report **Evaluated:** March 27, 2026 **System:** OpenClaw agent memory infrastructure on pop-os **Version:** Autoglia/memory-db v2.11.0 (distributed), v2.13.0 (latest on website) --- ## 1. What Is Autoglia? Autoglia is a structured SQLite-based memory system for OpenClaw/Clawdbot AI agents. It solves the fundamental problem that AI agents forget everything between sessions — every conversation starts from scratch. **Product positioning (from autoglia.com):** - One-time purchase ($19 intro, rising to $29) - Local SQLite database — no cloud, no subscription - Automatic recording at infrastructure level (no LLM cooperation needed) - Context recovery after compaction - Web dashboard included **What's actually installed on this machine:** - Core memory-db skill at `~/clawd/skills/memory-db/` (v2.11.0) - Live database at `~/memory.db` (6.7MB) - Various helper scripts in `~/autoglia-agent/scripts/` - Scheduled cron jobs for checkpointing, schedule sync, and background maintenance --- ## 2. Architecture — Five Layers Autoglia implements five distinct layers of memory infrastructure: ### Layer 1: The Database (SQLite) - Single file: `~/memory.db` - 56 tables covering contacts, projects, knowledge, conversations, tasks, ideas, content, outreach, meetings, reminders, preferences, businesses, background jobs, memory proposals, context packs, and more - WAL journal mode for concurrent reads - Schema version 14 (current as of v2.10.0+) ### Layer 2: Infrastructure-Level Recording (`sync-sessions.py`) - Reads OpenClaw's own JSONL session files directly - Runs on session start - Writes to `conversation_transcripts` table - Works even when the agent didn't save anything during conversation - No LLM cooperation required ### Layer 3: Automatic Checkpointing (`auto-checkpoint.py`) - Hourly cron job - Finds sessions with unsummarized messages (≥10 messages threshold) - Splits by inactivity gap (default 30 minutes) — separates Monday's chat from Thursday's - Extracts message snippets as raw text (no LLM) - Creates entries in `conversation_log`, `conversation_topics`, `session_stats` - **Zero API calls** — pure Python ### Layer 4: Context Recovery (`recover.py`) - Detects context compaction by checking JSONL transcript gaps - Reads database to reconstruct thread - Runs on every session start as a "session briefing" - Outputs: user identity, active projects, recent checkpoints, pending reminders, knowledge, personality profiles - Acknowledges compaction detection if found ### Layer 5: Background Memory Agent (`memory-agent.py`) - Runs every 15 minutes via cron (when cron scheduler supports 15-min intervals, otherwise hourly) - Entity normalization - Builds precomputed context packs for session startup - Scores memory health (5 metrics) - Detects conflicts - Stages extraction proposals to `memory_proposals` table - Lockfile-protected, idempotent across runs --- ## 3. Memory Persistence — How It Works ### Recording Flow ``` OpenClaw JSONL session files → sync-sessions.py → conversation_transcripts (raw) ↓ auto-checkpoint.py (hourly) ↓ conversation_log (summaries) ↓ recover.py (session start) ↓ agent context ``` ### Checkpoint Types | Type | Trigger | LLM Involved | Content | |------|---------|--------------|---------| | Auto-checkpoint | Hourly cron, ≥10 unsummarized messages | No | Raw snippets, first user message = topic | | Manual checkpoint | Agent calls `checkpoint.py` mid-session | Yes (agent writes) | Rich summary with decisions, follow-ups | ### Context Compaction Recovery The system detects compaction by: 1. Checking JSONL file modification times vs. last checkpoint 2. Looking for gaps in `conversation_transcripts` 3. If detected: pulls the lost conversation thread + recent checkpoints + active projects ### Data Storage Locations | Data Type | Table | Current Count | |-----------|-------|---------------| | Contacts | `contacts` | 11 | | Knowledge facts | `knowledge` | 289 | | Projects | `projects` | 27 | | Tasks | `tasks` | 8 | | Conversation checkpoints | `conversation_log` | 254 | | Raw transcripts | `conversation_transcripts` | 4,250 | | Daily logs | `daily_log` | 196 | | Ideas | `ideas` | 17 | | Content | `content` | 31 | | Background jobs | `background_jobs` | 3,946 | | Memory proposals | `memory_proposals` | 75 | | Context packs | `context_packs` | 5 | --- ## 4. Integration with OpenClaw/Clawdbot ### How it connects 1. **Session start protocol** (injected into SOUL.md/AGENTS.md via setup.py): ``` 1. Run sync-sessions.py 2. Run recover.py 3. If compaction detected, acknowledge briefly ``` 2. **Auto-memory rules** — the bot automatically: - Updates contacts after talking about people - Logs activities to daily_log - Inserts learned facts to knowledge - Saves preferences - Checks reminders at session start - Checkpoints every 5 conversations or session end 3. **Cron integration** — hourly checkpoint runs via `openclaw cron`, not user-level cron 4. **Heartbeat integration** — stats.py runs on heartbeats to check memory health 5. **Schedule bridge** — Autoglia-agent has bidirectional sync with Linn's bot: - `schedule_receiver.py` listens on port 5000 for incoming schedules - `schedule_bridge.py` polls and posts to Discord - `send_to_linn.py` sends outbound schedules - All entries land in memory_proposals for review ### What the bot sees The bot reads SKILL.md which tells it exactly which memdb.py commands to use. It doesn't have raw SQL access — only through the memdb.py CLI which enforces parameterized queries. --- ## 9. Gaps, Issues, and Observations ### Functional Gaps 1. **No fuzzy name matching** — "Linn" won't find "Lynn" if voice transcription gets it wrong. Planned for v3. 2. **No similarity scoring** — searches return exact matches only. Planned for v3. 3. **Auto-extraction not enabled by default** — facts must be manually inserted. The learning pipeline exists but requires either `memory.learning.enabled=true` (set) or `--enable-inference-jobs` flag (passed in cron). Both are configured correctly here, but the feature is still fairly new (v2.10.0+). 4. **Web dashboard not running** — dashboard.py exists but no indication it's running as a service. Would need to be started manually or as a systemd service. 5. **Two cron jobs in error state** — Daily morning check-in and YouTube Transcript Monitor failed recently. Not core Autoglia but worth investigating. 6. **No backup automation visible** — export.auto_backup is set to true in config, but no cron job visible for automated backups. May depend on manual triggers or the export.py being called from elsewhere. ### Observations 1. **Version mismatch** — Installed skill is v2.11.0, but website promotes v2.13.0. Should verify if newer version has significant fixes. 2. **Schema version 14** — Current, but the `user_schema_rev` is 0, meaning no extension tables have been created via the `create-table` command. However, many extension tables exist (emails, facebook_posts, etc.) — these may have been created manually or via older mechanism. 3. **Large background_jobs table** — 3,946 entries suggests the background agent has been running frequently. Worth checking if old jobs are being cleaned up. 4. **75 memory_proposals pending** — A proposal queue exists with 75 entries. These are staged non-deterministic extractions awaiting review. Should be periodically processed. 5. **5 context packs** — Precomputed context packs exist. Could check if these are being used effectively. 6. **Schedule integration** — The Linn bot schedule sync is a unique extension built on top of Autoglia. The receiver writes to memory_proposals rather than directly to the schedule tables. This is by design (proposal staging), but may be a point of confusion. 7. **Reminders table is empty** — 0 reminders in the database. Either not being used or there's a bug in creation. 8. **No visible test execution** — tests/ directory exists with pytest, but no evidence tests have been run or are automated. ### Minor Issues - **Documentation is split** — INSTALL-NOTES.md in autoglia-dev is more detailed about known issues than the main README. Could be consolidated. - **CHANGELOG.md shows version 2.11.0** in autoglia-dist, but the website shows 2.13.0. The changelog may be out of date or the distributed version is behind. - **Cron job naming** — "Autoglia pain signal detector" doesn't match the script name in autoglia-agent/scripts/ (pain_signal_detector.py exists but appears to be a different function). Worth verifying the script being called. --- ## 10. Summary Autoglia is a well-architected memory system that solves the context-loss problem for AI agents.
